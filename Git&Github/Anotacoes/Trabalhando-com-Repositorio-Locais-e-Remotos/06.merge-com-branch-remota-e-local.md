			 	Dois ou mais repo locais vs um repo remoto	

Suponhamos que fazemos alteracoes na branch e depois commitamos e fazemos push ao repo remoto.

Porem, outros membros da equipa, que estao a trabalhar directamente na mesma branch que nossa, mas cada um na sua maquina,
ainda nao tem estas alteracoes, localmente, para receber/puxar os commites do origin, devemos usar o comando:

git fetch origin

Porem, estas mudancas nao seram aplicadas automaticamente no nosso codigo/branch local, se verificar-mos:

git branch -a -v

veremos que as alteracoes ainda nao foram aplicadas, para aplicar, precisamos mesclar.

Como vimos anteriormente, para mesclar branches, a duas maneiras, com: **merge**/**rebase**

git merge origin master -m "mensagem"

Se não informarmos uma mensagem para o commit de merge, será
aberto um editor de texto.
	
		ou
		
git rebase origin/master

E pronto.


Ponto de atencao.

Devemos evitar fazer alteracoes directamente na branch principal, quando trabalhamos em equipa,
e seguro e aconselhavel que se criem branches para cada grupo/tarefa, e fazer merge com a principal no final.

Assim deixamos o historico mais limpo, e facil de ler,rastreiar...

Outra forma, e usando o 
git pull
 esse comando vai puxar os commits da branch remota e fazer o merge, em simultaneo.

Usando o git pull, e quase o mesmo que fazer git fetch e git merge origin/master

Podemos tambem usar o pull com o rebase tambem:
git pull rebase
